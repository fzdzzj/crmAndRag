# 近重复交换率重定价锚 v1（evidence-to-operations · G1）

> **本文件的每一个数字都来自 `bash scripts/rag-quality/near-dup-exchange-rate-report.sh` 的固定表格**（stdout 前缀 `[G1E][表 N/4 …]`，落盘 `target/near-dup-exchange-rate-report.txt`），无手算数字。
> 复算产出的机器可读锚：`docs/rag-quality/near-dup-exchange-rate-v1.json`（唯一写入口 = `NearDuplicateExchangeRateDecisionTest` 的写模式 `-Dnear.dup.exchange.write=true`，默认模式逐字节校验）。
> 上一卡锚 `near-dup-mechanism-decision-v1.json` **零改动**；两份锚的一致性由 E2 逐点校验兜住（R 与上一卡 M1 网格 200 点逐点相等）。

## 0. 一句话结论

**EXCHANGE-RATE（E6 第②支）：免费档不存在，但交换率已量出、汇率没人能定——价目表交 Owner 拍板，本卡不改任何生产常量。**

把上一卡混在同一个分母里的 276 对负样本泄漏拆成两半后：基线 3 对泄漏 = **2 对同文档抑制（有害半边，A1/A2）+ 1 对跨文档降权（无害半边，A3）**；
200 点网格上**不存在任何免费档**（E3：所有 `f* < 0.9887` 的点 `S_same` 都高于基线 0.02——same-class 有一对 0.988662 恰好卡在基线 floor 下方一步，
任何下探都先压掉它），但存在 R 提升档 ⇒ 交换率可定价。数值源自表 3/4 的 `verdict` 行与表 1/4、表 2/4 对应行。

## 1. 基线（表 1/4）

| 指标 | 值 | 出处 |
| --- | --- | --- |

| `R(f)` | 70/120 = **0.583333** | 表 1/4 |

与上一卡锚对账：`baseline.leakedNegative = 3` = `keptSame(2) + keptCross(1)`，`R(0.9887) = 0.583333` 逐值相等——**拆分不改变总量，只改变归因**。

## 2. 拆分口径（E1）与恒等式（E2）

- `R(f)` = 同源保留率（与上一卡 M1 同语义同网格：`cosine >= min(f, 0.9944)` 保留——网格顶部高于阈值的点不是物理档位，只为逐点相等而披露）；
- `S_same(f)` = same-class 对中 `cosine ∈ [f, 0.9944)` 的数量 ÷ 100（被 ×0.5–0.75 降权的同文档图占比，**有害量上界**）；
- `C_cross(f)` = cross-class 同区间数量 ÷ 176（无害量）；
- E2 恒等式：逐点 `keptSame + keptCross + dropped = 276`（200/200 全过，分析器内建抛错）；`R(f)` 与上一卡锚 200 点逐点相等（首次复算曾暴露
  floor>0.9944 段的平台语义差，已按上一卡 `tierOfCosine` 同语义修正后逐点相等）。

**跨文档半边的关键结构**：cross-class 余弦最高 0.98873594（恰在带内，即基线那 1 对），次高直接跌到 0.73——因此**在基线档及以下的 178/200 个网格点上 `C_cross` 恒为
1/176**（`f > 0.98873594` 的其余 22 点为 0，那是「比基线更严」的方向，不构成降 floor 的代价）：降 floor 的全部边际代价都落在同文档抑制上，跨文档噪声不再新增。这就是「拆开之后可拍板」的结构原因。

**读法（全部行来自表 2/4 的对应行）**：

1. **第一步就是纯亏**：`floor=0.9885`（网格上离基线最近的一步）`ΔR = 0`、`ΔS_same = +0.01`——把 0.988662 那对同文档图压进降权带，却换不回任何同源变体。
2. **免费档不存在的原因**：E3 要求 `S_same(f*) ≤ S_same(0.9887) = 0.02`；网格上所有 `f < 0.9887` 的点都把 0.988662 那对收进带内（`S_same ≥ 0.03`），条件全灭。
3. **最便宜的 R 提升档**（披露，非推荐）：`floor=0.988`，`ΔR = +0.008333`（多救回 1 对同源变体），代价 `+1` 张同文档图被降权；
   **累计交换率最高档**：`floor=0.982`，`ΔR/ΔS_same = 8.333333`（多救回 10 对、多压 1 张）。两者都只是价目表的一行，**不是推荐档**。
4. 摸到上一卡 C1 门槛（R ≥ 0.90）最近的是 `floor=0.92`（R=0.916667）：代价是同文档抑制 2% → 8%（6 张）。
5. 逐 kind 保留数随 floor 的分布（如 `floor=0.90`：jpeg-q80=24 / scale-085=24 / scale-070=24 / crop-04=24 / crop-12=17）见表 2/4 `kinds=` 列——
   crop-12 仍是跌幅最大的档，与上一卡结论一致。

## 5. 假设登记（锚 `assumptions` 逐字回显，禁隐含）

- **A1** 同文档 ⇒ 可能相关。这是**假设**，不是真值；真值需查询-相关性标注，本卡不做。
- **A2** 被降权的同文档图**只有与查询同时进入同一 top-k 才有害**；本卡不测共现，故 `S_same` 是**有害量上界**，必须如实标注。
- **A3** 跨文档降权视为无害（噪声抑制），只计数、不记代价。

## 6. 未定项与后续卡边界

1. **档位由 Owner 拍板，改常量须新卡**：本卡不改 `ImageSimilarityGate` 任何常量（threshold=0.9944 / floor=0.9887 / 权重 0.75|0.6|0.5 逐字不动，
   锚 `productionConstants` 由守卫测试逐值比对）。价目表只回答「每降一档，多救回多少同源变体、多压掉多少同文档图」，**不回答「这个价能不能接受」**——
   后者需要 A1/A2 的真值（查询-相关性标注）或业务对误召回的处置成本，属于 Owner 决策。
2. **查询-相关性标注语料**（后续操作单要点，本卡不做）：给 100 对 same-class 打「同查询下是否应召回」标签，把 `S_same` 从上界变成实测伤害；
   届时免费档判据（E3）可用同一分析器重跑（锚重锚 = 新卡）。
3. **0.988662 这对 same-class 是当前数据的「卡位对」**：任何下探都先压它。若业务裁定该对属「同版面不同数据」（本就应压），免费档判据可能翻转——
   这正是 A1 需要真值的原因，本卡不预判。
