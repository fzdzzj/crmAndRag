# 检索上下文快照批读前后对照（update-context-snapshot-batch-read）

> 2026-09-26 当轮实测。证据级别：**本机真实存储（一次性 MySQL/Qdrant 容器）+ 本地确定性模型桩**，同 `docs/representative-hotpath-measurement.md` 的显式 opt-in 入口（`RepresentativeHotpathBenchmark`，`REPRESENTATIVE_HOTPATH_MEASURE=1`），不是生产 RTT，不得外推生产收益。旧报告（request-hotpath-baseline / representative-hotpath-measurement / hotpath-concurrency-attribution）的历史数字原样保留、不与本文混算。缺失 `chunkIndex` 的拆箱缺陷为独立正确性事项，本案未触碰、其数据也未计入本文任何结论。

## 0. 执行结论（先读这段）

1. **调用形状收敛成立**：五命中固定负载的检索快照 SQL 从每请求 10 条（5×`selectById` 子块 + 5×`selectList` 邻居）收敛到 2 条（1×`selectBatchIds` 子块批查 + 1×`selectList` 多文档/多序号邻居批查），含授权 3 + 稀疏 1 后每请求 SQL 总数 14 → 6，真存储基准的硬断言（逐请求 c1 + 轮级 c8）两执行全绿。
2. **目标分段延迟收益可复现**：c1 稳态（两执行 round 2）上下文分段 12.270/11.462 ms → 5.141/5.645 ms（-58%/-51%，同向）；c8 两个窗口的上下文分段同向下降（120.694→57.523、56.053→32.884、180.190→51.300、63.331→39.700 ms）。批查单条 SQL 比旧的逐命中单条更重（c1 平均每条 SQL 1.37 → 2.55 ms，邻居批查返回跨文档×序号行集），但往返次数与分段总墙钟双降。
3. **端到端无收益，不能宣称加速**：c1 稳态端到端 P50 29.279/28.073 → 30.120/31.335 ms（+2.9%/+11.6%），P95 39.879/34.439 → 35.096/35.688 ms（持平），吞吐 31.534/34.629 → 32.751/30.713 req/s（持平）。端到端由授权 SQL（3 条）与 Qdrant 检索（4 次）主导，快照分段约占 c1 稳态端到端的四成，其减半未转化为端到端改善。**本机端到端收益：无**；生产收益：未知。
4. **语义等价与失败语义无回归**：原新路径对照（测试内复刻旧逐命中算法）12 场景输出逐字等价，覆盖父块/邻居混合、父块缺行、非数字 id、快照缺行、重复命中、跨文档隔离、首末块、同页取舍、开关关闭、空命中；批查异常有界回查（受影响主键/命中恰好一次）与持续故障降级（查询次数有界）有测试锁定。四条真存储执行（前后各两轮）检索 0 失败、摄取 0 失败，摄取形状与轮次复位断言全部不变（27 SQL/文档，与改动前逐项一致）。
5. **裁决与验收口径记录（不事后改写门槛）**：规范差异「负载不可比或无稳定改善」要求"延迟/吞吐结果不能支持同向改善"时停止交付，但未指明"延迟/吞吐"指目标分段还是请求端到端。本案按以下口径裁决并留痕：**结构性降次**（快照 SQL 14→6/请求）与**目标分段**（上下文段）墙钟下降两项复现成立；**请求端到端**的延迟/吞吐在两次独立执行的稳态对比中未获同向改善（P50 两次均略差、P95/吞吐互有涨跌）。据此，本变更以「保留结构性 SQL 降次 + 分段改善、**不宣称任何请求端到端或生产加速**」的决策合入；合入前提中真正的一票否决项（输出/权限/失败语义回归）不存在。该歧义按上述口径明示解决，spec-delta 与既有门槛未做任何改写或放宽；若 owner 要求以端到端口径重新裁决，另案立项并以端到端为准重新验收。
