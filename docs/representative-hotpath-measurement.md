# 本机隔离环境请求热路径度量（add-representative-hotpath-measurement）

> **性质**：只度量，不改生产行为。检索与摄取主路径接**本机一次性 MySQL/Qdrant**——生产 Flyway 迁移链建库、生产 MyBatis-Plus
> mapper/SQL/索引、生产授权 SQL（非超管 owner 路径）、生产 Qdrant gRPC 客户端与 payload 逐库过滤；模型 embed/chat/查询改写
> **硬绑定确定性本地桩**（不读任何真实密钥，env 与仓库 `.env` 都不读）。证据级别 = **本机真实存储 + 本地模型桩**，
> **不是生产 RTT**，不得外推生产瓶颈，不构成任何生产优化或费用授权。
> **日期**：2026-09-25
> **机器**：Windows 11 家庭版（10.0.26200）/ Intel Core Ultra 7 255HX（20 逻辑核）/ 15.4 GB RAM（与旧基线同机）
> **JDK**：Oracle JDK 21.0.9；**JaCoCo agent 挂载**（surefire 默认 `@{argLine}`，实测 `jacoco_agent=attached`）——计时有观测开销
> **镜像**：`mysql:8.0`（本地预存在，约 1.1 GB）/ `qdrant/qdrant:v1.18.3`（本地预存在，约 270 MB）；一次性容器随 JVM 结束销毁，零镜像下载
> **基线 HEAD**：master @ `5584fd0`
> **复现**：`REPRESENTATIVE_HOTPATH_MEASURE=1 mvn -B -ntp -Dtest=RepresentativeHotpathBenchmark test`
> （stdout 搜 `REPHOT` 行；surefire 报告 `TEST-com.slz.crm.quality.RepresentativeHotpathBenchmark.xml` 的 system-out 有同样内容。
> 默认 `mvn test` / `mvn verify` / merge-gate **发现不到也不运行**该入口；开关缺失、Docker 不可用、镜像缺失一律 fail closed。）

## 0. 执行结论（先读这段）

1. **度量真实跑通**：同一次 JVM 内两轮（round 1/2）同负载全流程完成，且整条命令复跑一遍共 4 组相位数据；全部调用形状断言、
   摄取样本初始状态复位断言、逐库过滤覆盖断言通过。零外发、零真实密钥读取、零镜像下载。
2. **挖出一个生产侧缺陷（重要发现）**：`QdrantVectorStore#search` 把 gRPC `ScoredPoint.getScore()`（float→Float 装箱）强转
   `Double`，对**真实 Qdrant 的任何非空命中恒抛 ClassCastException**（旧合成基线用内存桩返回 Double 分数，从未触发）。
   本案不改 `src/main`：检索经测试侧 shim 运行（§5），缺陷修复需**另案**。
3. **本机口径下的分段画像（候选调查项，非结论）**：检索稳态（单并发）以 **context 段（含父块展开 + 邻居共 10 次快照 SQL，嵌套）**
   与 **Qdrant search 段**占比领先；摄取被 **24 条单条自动提交 insert**（切片快照写库，≈每条 18.6–19.0 ms）绝对主导。
   按规格这只能列为待验证候选——真实模型远程 RTT 未知、生产瓶颈未定，下一张生产优化提案必须在相应真实/代表性环境同负载重测
   或取得 owner 授权后才能选类；不得据此自动实施逐库并行、批量 embedding、JVM/GC 调参。
4. **c8 并发档两轮波动大**（p50 106.8–248.8 ms），按规格记「**无法归因**」，不在本文下任何结论中使用该档做占比比较。

| 项 | 值 | 与旧基线 |

**实测语料规模**：4 库各 1 份文档、**每文档 11 子片**（REPHOT corpus：chunks=11 vectors=11 ×4），合计 44 切片行 + 4 文件行——
与旧基线「≈11 片」一致。

**与旧基线的一处已记录差异**：基准用户名下还有第 5 个库（摄取库 90001，owner 同人）。首轮实测（scope 传空）抓到检索**逐库 5 次**
而非 4 次——这是真实授权语义下的合法结果，属负载差异证据，不改旧数字。为保持「4 个已授权 KB」可对照，正式采集改为
`kbScope=[1,2,3,4]`（走生产 scope 收敛路径，授权 SQL 形状不变）。

### 1.2 隔离与初始数据状态

- 一次性容器：`crm_rephot` MySQL（Flyway `classpath:db/migration` 全链迁移 + 种子 5 库，owner=`user:10001`）与 Qdrant
  集合 `representative_hotpath`（32 维 Cosine），随 JVM 结束销毁；运行前后本机无残留容器（实测）。
- **每轮摄取前后数据规模断言**：`document_vector_chunk` 44 行 → 44 行，`uploaded_file` 4 行 → 4 行（两轮、两次执行均通过）——
  每样本复位（物理删切片行/文件行 + 生产 Qdrant `deleteByDocumentId`）都在**计时窗口之外**，样本初始状态恒定，
  检索种子库（1–4）不受摄取写入影响。

## 5. 生产缺陷发现与测试侧 shim（必须披露）

- **缺陷**：`src/main` 的 `QdrantVectorStore#search`（约第 171 行）把 gRPC `ScoredPoint.getScore()`（float，装箱为 Float）
  强转 `Double`。对真实 Qdrant **任何非空命中**都会抛
  `java.lang.ClassCastException: class java.lang.Float cannot be cast to class java.lang.Double`（重试 3 次后失败，
  首轮实测栈已留存）。旧合成基线（内存桩返回 Double 分数）与现有 mock 单测均不可见该缺陷。
- **本案处置**（不改 `src/main` 的硬边界下）：新增测试侧
  `RepresentativeHotpathQdrantSearchShim`（`src/test/.../knowledge/vector/`）——向量写入/删除**原样委托生产**
  `QdrantVectorStore`；search 用与生产同构的真实 gRPC 客户端 + 生产 `QdrantReflectionSupport#toFilter`（逐库授权过滤）
  + 生产 `toMetadata`（payload 读回），**仅修正分数装箱（float→double）与命中映射**。
- **影响**：§3/§4 的 qdrant_search/向量写删段仍是「真实 Qdrant + 生产过滤条件」；search 的编排水位（超时/重试语义）与生产
  `QdrantVectorStore` 有 shim 级差异。修复缺陷需**另案**（含真实 Qdrant 的 search 回归用例）。

## 7. 解读边界

- 次数是**断言**（每请求/每轮逐项校验）；耗时是本机单次运行记录，**跨机不可比**，不入门禁、不进 CI、不写入任何阈值。
- 本报告不修改 `docs/request-hotpath-baseline.md` 的任何合成数字、断言与结论；两份文档证据级别不同（合成假端口 vs 本机真实
  存储 + 本地桩），互不覆盖。
- 单机低并发结果**不得**外推生产 P99、扩容能力或资源预算；「检索数据库桶/context 段领先」「摄取 insert 主导」均为本机条件
  口径下的候选观察，不是改动授权。
- 与旧基线的负载差异只有两处且已披露：授权从桩换成真实非超管 SQL（多 3 条 SQL/请求，旧基线无此项）；摄取库独立 + 每样本复位
  （旧基线写 KB1 不复位）。
