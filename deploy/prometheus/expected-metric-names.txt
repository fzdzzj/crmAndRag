# ================================================================
# /actuator/prometheus 实际导出名清单（TASK-16 真相采集，消费端资产唯一名字来源）
# ================================================================
# 来源：真实 Spring 上下文启动（profile=test，H2，无 Docker）后 MockMvc 打
#       GET /actuator/prometheus，解析 exposition text 的 # TYPE / 样本行得到。
#       采集用例：src/test/java/com/slz/crm/platform/monitoring/PrometheusExportTruthCaptureTest.java
# 重生成：mvn -B -ntp test -Dtest=PrometheusExportTruthCaptureTest
#         用 target/prometheus-export/expected-metric-names.txt 覆盖本文件（保留本头注释）。
#         改线程池/指标生产端（PlatformAsyncConfig、TaskExecutorMetricsBinder、
#         MemoryBypassTaskExecutor）后必须重跑，否则本清单与真库导出脱钩。
# 格式：<metric-name> [label-key,label-key,...]   label 键为该名下所有样本出现过的并集，升序
# 禁止手抄/推断：Micrometer→Prometheus 的改名规则（点转下划线、counter 追加 _total、
#       gauge 按 baseUnit 追加单位后缀）只有注册表本体说了算。
#       历史教训：alert-rules.yml 曾查裸名 async_task_rejected（真名带 _total）→ 告警永不触发；
#       dashboard 曾查 executor_threads_active / executor_queue_size（真名
#       executor_active_threads / executor_queued_tasks）→ 面板恒 No data。
# 采集时间：2026-09-20（micrometer 1.15.3 / prometheus-metrics 1.3.10 / Boot 3.5.5）
# 说明：本清单是"允许被消费端引用的名字"白名单，不是运行期全集——
#       运行期还会按活动出现 http_server_requests_seconds_*、qdrant/minio 等族。
# ================================================================
