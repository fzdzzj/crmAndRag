# 规范差异：request-hotpath

本文件约束请求级性能基线。它不改变检索、摄取或运行时配置。

## ADDED Requirements

### Requirement: 同一负载测量两次
WHEN 运行请求级基线,
系统 SHALL 对同一检索负载和同一摄取负载分别做零延迟与注入延迟两遍测量。

#### Scenario: 输入不变
GIVEN 检索为 4 个授权库、1 条查询、topK 5，摄取为 24 个子块
WHEN 跑零延迟和注入延迟
THEN 两遍的输入和调用顺序配置相同
AND 只改变假端口上的延迟

#### Scenario: 不连外部系统
GIVEN 基线测试启动
WHEN 执行测量
THEN 不调用真实嵌入服务
AND 不连接 MySQL 或 Qdrant

### Requirement: 先记录次数再解释时间
WHEN 基线完成一遍,
系统 SHALL 记录嵌入次数、向量检索次数、SQL 次数和写库次数，并分开记录本地墙钟与注入时间。

#### Scenario: 检索调用形状
GIVEN 4 个授权库和 5 个命中
WHEN 零延迟检索结束
THEN 向量检索次数等于授权库数
AND 邻居查询次数等于命中数
AND 这些次数被断言，而不是只打印

#### Scenario: 注入时间不算本地 CPU
GIVEN 第二遍给远程调用和 SQL 加了延迟
WHEN 解释零延迟遍的耗时
THEN 将零延迟墙钟只标记为测试侧本地路径时间，不称作纯 CPU 或生产业务规则时间
AND 不把注入延迟加进 CPU 或 GC

### Requirement: 未观测项不能指导改动
IF 测试没有采集锁等待、GC 日志或 JFR,
系统 SHALL 把锁、GC 和 JVM 标为未观测，并且不修改它们。

#### Scenario: 没有 GC 证据
GIVEN 测试只得到墙钟和调用次数
WHEN 选择下一类改动
THEN 不选择 GC 或 JVM 参数
AND 不修改线程池和超时

### Requirement: 合成占比不得直接决定生产优化对象
WHEN 基线文档解释零延迟和注入延迟结果,
系统 SHALL 将不同桶占比标记为特定注入参数下的条件结论，而不是生产瓶颈证据。
系统 MUST NOT 据此要求下一张生产改动提案只能修改远程、数据库或本地业务规则中的某一类。

#### Scenario: 合成远程单独领先
GIVEN 假端口注入 30/20/5 ms 后，远程桶比数据库桶高 41.4 个百分点
WHEN 文档写出后续动作
THEN 写明该领先仅对所设延迟与固定负载成立
AND 不据此开展逐库并行、批量嵌入或 JVM 调参的生产改动

#### Scenario: 实际耗时与合成假设相反
GIVEN 后续代表性环境采样发现数据库或授权/查询改写耗时高于假端口远程桶
WHEN 决定下一案优化对象
THEN 以该实测分段占比为准，不能沿用合成场景的远程结论
AND 改动前记录同负载延迟、吞吐与资源占用基线

#### Scenario: 尚无实际分段证据
GIVEN 只有本离线测试的计数与注入延迟
WHEN 确定下一步
THEN 先设计不自动付费的真实或代表性环境度量方案，外呼与成本节点另获 owner 批准
AND 下一类生产优化因素维持未知
