# 规范差异：document-ingest 切片写库批次化

本增量只约束摄取内部数据库写入与同负载验收；不修改 `document-chunking` 已有父子块、幂等重建和失败清理契约，也不授权在途视觉 PDF 试点或任何真实模型费用。

## ADDED Requirements

### Requirement: 批写保持切片主键和父子语义
WHEN 已通过写授权的文档产生待持久化切片,
系统 SHALL 以受限大小的数据库批次持久化切片；父块数据库自增 ID 可用后才能给所属子块写 `parent_chunk_id`，子块数据库 ID 可用后才能创建向量记录及引用 `chunkId`。系统 MUST 保持原文、chunkIndex、锚点、角色、父子分组、子块顺序和逻辑行数不变，不得更改迁移或自造另一种业务 ID。

#### Scenario: 固定切分 24 子块
GIVEN 同一文档按固定策略产生 24 个子块且没有父块
WHEN 写入快照并准备向量记录
THEN 数据库仍有 24 个 CHILD 行、0 个 PARENT 行且 24 个子块 ID 非空、唯一
AND 每个向量 chunkId 与对应 DB 主键逐一相等，嵌入输入及调用次数不变

#### Scenario: 语义切分父块
GIVEN 一个逻辑段拆出至少两个子块且需要父块全文
WHEN 批次写入
THEN 父块先取得自增 ID，子块的 parent_chunk_id 均指向正确父块
AND 父块不产生 embedding/向量，子块及来源锚点仍对应原顺序

#### Scenario: 大文档与生成键不可用
GIVEN 子块数超过单批安全上限，或所选批处理在真 MySQL 无法可靠逐行回填主键
WHEN 评估写入策略
THEN 前者拆成有限大小批次且不新增无界 SQL/参数或批处理缓冲，原有整文档集合不在本案改动
AND 后者停止生产批写实施并报告不可用，不改变冻结 ID 或数据库结构来绕过前置闸

### Requirement: 写库批次不扩大事务或失败可见性
IF 一批切片写入失败、生成键不完整，或后续嵌入/向量 upsert 失败,
系统 SHALL 按现有 `ingest/reingest` 失败语义分别尝试删除该文档向量与物理切片、保留原文件、标记 FAILED；清理本身失败 SHALL 告警并披露残留风险，不得把批次异常误报成功。数据库事务 MUST NOT 跨文件/模型/向量库 I/O 长时间持有连接；审计与异步衍生问题的触发时机 SHALL 不变。

#### Scenario: 批次中途失败
GIVEN 已有部分子块行写入或部分主键回填
WHEN 后续子块批次失败
THEN 不创建半量成功的向量引用，分别尝试物理清理已写切片和删除向量，并标记文档 FAILED
AND 同 documentId 再次写入时不因逻辑删除行占用唯一键而失败

#### Scenario: 外呼失败不回滚失败标记
GIVEN 切片数据库写入成功而第 N 个 embedding 或 Qdrant upsert 失败
WHEN 进入失败清理
THEN 对已提交切片发起按文档物理清理、对向量发起删除；正常清理完成后不留半量检索结果，原文件和 FAILED 错误状态仍可查询
AND 清理任一子操作失败时分别告警并保留残留风险记录；未持有覆盖外呼的数据库事务或因它回滚掉 FAILED 标记

#### Scenario: reingest 与授权边界
GIVEN 现有文档已入库并有写授权用户发起重建
WHEN 旧行物理删除后新批次失败或再次重试
THEN 按既有口径清理半量切片与向量并记录审计，重试不会撞 `(document_id, chunk_index)` 唯一键
AND 无写授权的请求在文件、批次、模型和向量操作前被拒绝

### Requirement: 主验收为摄取端到端而非数据库段
WHEN 比较旧单条写入与新批次写入,
系统 SHALL 在相同 c4 负载、种子、预热、每轮样本、假模型、本机隔离 MySQL/Qdrant 和观测口径下取得实施前后的新鲜测量（每侧至少两独立执行），分别记录逻辑行数与可观测的数据库物理执行/提交次数（缺测标 unknown，Mapper 调用不等于提交）、写入段、端到端 P50/P95、成功吞吐、错误和资源；旧历史报告 MUST 保持原样。端到端改善是合入生产批写代码的主门槛，不能以写入段下降替代。

#### Scenario: 端到端收益可比
GIVEN 前后负载、有效配置、初始数据及成功逻辑行数一致
WHEN 比较两侧 c4 稳态轮
THEN 报告每次执行的 P50/P95、吞吐、失败、写库段、提交次数与测量噪声
AND 只在端到端改善在独立执行中同向且可区别于前测漂移、P95/错误及吞吐不重复退化时接受优化结论

#### Scenario: 分段变快但请求无收益
GIVEN DB 往返/提交次数与切片段时间下降，但摄取端到端 P50/P95 或吞吐未显示稳定改善
WHEN 汇总验收
THEN 记录“假设未获支持/无法判定”，停止生产批写代码的提交与合并
AND 不改写本门槛、不靠 JVM/连接池或并行模型调用追指标，也不宣称生产收益

#### Scenario: 默认执行与缺失环境
GIVEN 未显式 opt-in，或本地 Docker/镜像/确定性假模型保护条件缺失
WHEN 执行默认测试或尝试本机度量
THEN 默认测试不发现度量入口，缺失条件时在付费调用和下载镜像前失败并报告未测
AND 不读取真实密钥、不调用真实模型、embedding 或 vision Provider，不启用生产开关
