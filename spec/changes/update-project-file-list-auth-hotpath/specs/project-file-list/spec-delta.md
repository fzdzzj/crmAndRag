# 规范差异：project-file-list 读取与授权热路径

本案只为项目文件列表建立真实同负载证据，并在权限等价可证明且请求级收益稳定时才允许单因素优化；不更改既有列表 API、文件下载权限或页面 total 口径。

## ADDED Requirements

### Requirement: 项目文件列表有可隔离的请求级前测
WHEN 评估 `queryPage` 的性能,
系统 SHALL 使用生产列表服务和记录级鉴权实现，在一次性本地 MySQL、确定性用户/关联业务/文件种子下测量至少两次独立执行；按页大小、权限分布、冷暖缓存分别记录页查询、用户状态、权限、业务归属、名称转换、令牌签发的 SQL/耗时，以及端到端 P50/P95、吞吐、错误和资源。不可观测项 SHALL 标 unknown，不得以代码 2N 判定形状冒充实测瓶颈。

#### Scenario: 同页不同可见比例
GIVEN 同一 pageNum、筛选与排序下分别构造 10/50/100 条的全可见、部分可见及全无权页面
WHEN 用有效非超管用户请求列表
THEN 每组记录 total、records ID/顺序、链接有无与分段 SQL 次数、端到端 P50/P95 和吞吐
AND 页内过滤后的不足额/空页仍按现行口径记录，不擅自补齐下页

#### Scenario: 超管和非在职用户
GIVEN 超管、普通角色、冻结/离职用户及相同文件种子
WHEN 运行基准
THEN 按现行用户状态/角色逻辑分别记录结果，失效用户不得因测量或优化获得下载链接
AND 不将超管快路径的 SQL 分布冒充普通用户开销

#### Scenario: 缓存与环境门控
GIVEN 上传人姓名缓存可命中或尚未预热
WHEN 重复测量相同负载
THEN 冷暖状态分别报告，不能将已缓存名称读取记作每行数据库调用
AND 默认 surefire/merge-gate 不发现真库入口；缺 opt-in、Docker 或本地镜像时在拉取镜像或连接业务库前停止并记未测

### Requirement: 权限、分页和令牌语义不因优化改变
IF 前测显示一类重复读取稳定占优且要优化它,
系统 SHALL 保持 `queryPage` 的 total 为数据库条件总数、records 仅由当前页可读行构成且顺序不变；每个签发的项目文件令牌 MUST 只绑定当前有权用户，下载时 MUST 继续按当前用户和记录级归属重新复核。系统 MUST NOT 跨请求缓存活跃用户、角色权限、业务归属或以单个文件外键代替多维度可读判定。记录级权限判定 MUST 使用判定时刻数据库中该用户的当前角色，MUST NOT 复用请求早期状态闸读到的旧 roleId。

#### Scenario: 多归属与订单反查
GIVEN 文件可关联活动、商机、合同或订单项，且某用户仅经其中一个维度可读
WHEN 列表判断并签发链接
THEN 授权结果与原有任一合法维度可读的规则相同，订单仍按其现有合同反查优先口径判断
AND 其他无权文件既不出现在 records，也不获得下载链接

#### Scenario: 分页总数与空页
GIVEN 数据库页内混有授权与无权行，或全部无权而数据库 total 非零
WHEN 查询列表
THEN total、页号、原页中的 records 顺序及可见子集与原实现一致
AND 不从下一页填充、不过滤 total，也不以未获授权文件生成 VO 或签发令牌

#### Scenario: 授权撤销与下载
GIVEN 列表生成时文件有权，之后用户权限、状态或归属被撤销
WHEN 使用此前签发的下载令牌
THEN 下载入口仍按 JWT/令牌用户及当前记录级权限拒绝该请求
AND 若页内复用授权判定无法保证原有签发时序，则保留第二次判断，不以省 SQL 为由改变撤权语义

#### Scenario: 判定期间角色被改派
GIVEN 列表或下载判定链已读取用户在职状态与当时角色，随后另一事务将该用户改派为无权角色并提交
WHEN 该请求继续执行记录级权限判定
THEN 判定按改派后数据库中的当前角色进行，无权文件既不出现在 records 也不获得下载链接
AND 不得以首次读取的旧 roleId 继续放行

#### Scenario: 独立文件与其他列表入口
GIVEN 文件没有业务归属，仅上传人或超管有权，且四条 `listBy*` 仍使用共享协作类
WHEN 实施仅 `queryPage` 的优化
THEN 独立文件放行范围及其他列表入口的现有输出、令牌签发和鉴权均不变

### Requirement: 仅单因素且端到端获益才交付生产优化
WHEN 前测归因完成且考虑修改生产列表路径,
系统 SHALL 只改变一个经请求级证据点名的开销类别，前后保持相同种子、角色、权限快照、页大小、缓存状态与测量口径，至少两次独立执行比较端到端 P50/P95、吞吐、错误和 SQL 分类。SQL 次数下降、缓存命中或静态 N+1 形状不足以单独构成验收，生产收益仍待生产环境验证。

#### Scenario: 可比且稳定改善
GIVEN 旧新路径逐页 total、records、令牌与撤权复核等价，且单类开销由前测稳定点名
WHEN 同负载复测
THEN 新报告展示各执行原始分位、吞吐、SQL 类别、失败和资源，端到端改善须同向且可区别于前测漂移
AND P95/错误及吞吐不重复退化，才允许交付生产优化代码

#### Scenario: 无清晰主因或安全无法等价
GIVEN 多类开销未能单独领先、冷暖缓存漂移、或二次鉴权/签发时序无法保持
WHEN 做交付裁决
THEN 只记录基线或否定结果，不合并生产鉴权优化
AND 不改变分页 total、令牌下载、权限矩阵、数据库迁移或 JVM/连接池参数来追指标
