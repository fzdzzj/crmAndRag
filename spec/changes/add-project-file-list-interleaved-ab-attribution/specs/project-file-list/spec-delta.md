# 规范差异：project-file-list 交错 A/B 性能归因

本案只为原 `update-project-file-list-auth-hotpath` 的 S2 性能裁决补证；原权限、分页、令牌和生产代码不变。既有「请求端到端改善须可区别于前测漂移」要求不被放宽。

## ADDED Requirements

### Requirement: 项目文件鉴权优化有安全同构的交错对照
WHEN 比较优化前 A 与安全修复后 B 的本机请求性能,
测试系统 SHALL 固定可审计的两臂代码身份、相同测试侧度量入口与种子、同一镜像及负载；SHALL 在执行前固定 A/B 顺序、独立 run 数、失败重跑规则和指标口径。A 不得采用角色改派回归为红的实现；任一臂的角色改派、撤权、分页或令牌反例失败时 MUST NOT 宣称性能 GO。

#### Scenario: 同机双序交错
GIVEN A 为 `31ba8c4`，B 为 `d67c7e9`，两臂测试入口字节相同且角色改派回归为绿
WHEN 以预先登记的 `AB, BA, AB, BA, AB, BA` 六对顺序运行
THEN 每臂至少六次独立 run，每次按原 10/50/100 页、冷暖缓存、权限分布和并发相完成两轮
AND 原始输出逐 run 记录顺序、条件行、失败、种子/镜像身份，不得事后删选不利窗口

#### Scenario: 环境或实现不具备可比性
GIVEN Docker、已存在本地镜像、测试源码同构或本地假身份任一前提缺失
WHEN 尝试执行真库基准
THEN 在拉镜像或连接业务库前停止，并把该格记为未测
AND 默认 surefire/merge-gate 不启动容器，真实模型和外部业务数据不被调用

### Requirement: 性能裁决区分配对效应和时间漂移
WHEN 对 A/B 测量做性能裁决,
报告 SHALL 以预注册的六个配对 run 为实验单位比较被改路径端到端 P50 主指标，同时展示 P95、吞吐、错误、SQL 形状、冷暖与 c1/c8 全矩阵；SHALL 报告同代码 A→A 安慰剂漂移、两种执行顺序和未改路径阴性对照。条件格不是独立重复实验；SQL 调用减少、单项严格区间分离或局部改善 MUST NOT 单独替代端到端归因。

#### Scenario: 本机性能接受
GIVEN 两臂安全与页面输出一致、各 run 完整且有效
WHEN 六对等权对数 P50 差均改善、AB 与 BA 各自中位差均改善、六对中位幅度大于四次 A 安慰剂相邻 run 最大绝对同代码漂移，且 P95 改善与吞吐不降各至少四对、两种顺序各自中位值均不退化、失败为零、阴性对照未出现可比幅度改善
THEN MAY 将 B 的**本机性能**裁决从未定更新为有条件 GO，并完整披露效应及不确定性
AND 不推断真实生产收益或改写历史原始数据

#### Scenario: 漂移未分开或发生安全失败
GIVEN 配对效应与安慰剂/未改路径同量级、次序反转、尾延迟重复退化，或任一安全反例失败
WHEN 做结论
THEN 维持未定或记 no-go，具体失败和缺失证据须列明
AND 不因性能结论回退已验证的当前角色鉴权安全修复，不以调 JVM/池参数掩盖噪声
