# add-ai-customer-360-insight — 客户 360° AI 智能商业诊断与会话交互深化

## 背景与动机

- 在完成全站业务实体语义检索大一统接入（`CUSTOMER`、`BUSINESS_ACTIVITY`、`SALES_OPPORTUNITY`、`CONTRACT`、`CONTACT_TASK`）后，系统已具备深厚的底层向量召回与检索能力；
- 但目前 AI 助手的定位仍偏向**“被动响应”**（用户问一句查一句、帮填单草稿）；销售在实际拜访或复盘时，最核心的诉求是：**无需手动翻查 5 个子菜单，即可一键获取目标客户的全生命周期商业诊断画像**；
- 此外，AI 会话生命周期与交互体验存在微观断点：会话标题固定为“新对话”缺乏智能提炼，AI 抽屉缺乏常见高频场景的快捷指令药丸引导；
- 本卡立项推进 **“客户 360° AI 智能商业诊断与会话交互深化”**，打通多实体聚合分析模型，实现从“被动检索”向“主动决策赋能”的质变。

## 变更内容

### 1. 客户 360° 多维数据聚合提取（CustomerInsightCollectorSupport）

- 针对输入的目标客户 ID（`companyId`），在权限边界内聚合以下五维业务快照：
  1. **客户基础画像**：公司规模、所属行业、当前状态、跟进负责人与归属部门；
  2. **跟进活跃度**：关联跟进活动（`business_activity`）总数、近 30 天跟进频次、最后一次跟进时间及距今天数、最新跟进摘要；
  3. **商机推进健康度**：关联销售商机（`sales_opportunity`）数量、预估总金额、商机阶段停滞天数、审批驳回/修改历史（`sales_stage_approval`）；
  4. **合同履约与资金状况**：关联合同（`contract`）总数、签约总额、已回款金额（`payment_record`）、待确认或逾期未回款金额；
  5. **待办任务与联系人覆盖**：未完成高优待办任务数（`contact_task`）、关键决策人与联系人覆盖数（`customer_contact`）。

### 2. 双层诊断引擎：确定性规则评分 + LLM 智能深度洞察

- **底层规则评分引擎（确定性量化）**：
  - 计算确定性健康分（0~100 分）：
    - 活跃度维度（30%）：跟进间隔 ≤7天满分，>15天扣分，>30天扣重分；
    - 商机健康度（25%）：阶段停滞过久或频繁驳回扣分；
    - 合同回款履约（25%）：逾期未回款或款项未结清扣分；
    - 任务与联系人（20%）：无关键联系人或高优任务超期扣分；
  - 评级映射：`EXCELLENT`（85-100）、`HEALTHY`（70-84）、`WARNING`（50-69）、`CRITICAL`（< 50）；
  - 提取规则风险警示（如：“超过25天未跟进”、“存在未结清款项”）。
- **上层 LLM 商业洞察引擎（ModelProvider 驱动）**：
  - 输入多维聚合数据与规则警示，调用 `ModelProvider` 生成结构化输出：
    - `summary`：一句话客户全景商业画像摘要；
    - `riskAlerts`：关键流失与成单阻碍风险点；
    - `actionSuggestions`：针对性的销售下一步拜访跟进建议；
  - **双层安全降级保障**：若模型未装配、超时或外呼异常，安全回退到规则层生成结果，绝对不阻断接口、不抛 500。

### 3. API 端点与权限同锚

- 新增端点：`GET /ai/insight/customer/{companyId}`；
- 鉴权与安全闸：
  - 挂方法级注解 `@RequirePermission(PermissionOperates.CUSTOMER_VIEW_COMPANY)`（复用 117，读写同权同常量，零新增权限码）；
  - 前置校验当前用户是否有权访问该客户（复用 `DataScope` 守卫，跨部门不可见客户返回 12002，防止越权诊断）。

### 4. AI Tool 自然语言调用注册

- 在 `AiToolRegistry` 注册只读查询工具 `getCustomerInsight`：
  - 参数：`companyId`（必填，客户ID）；
  - 描述：“获取指定客户的 360° AI 商业健康度诊断、流失风险预警与下一步拜访建议”；
  - 权限同锚：映射到 `PermissionOperates.CUSTOMER_VIEW_COMPANY`（117）；
  - 用户在 AI 对话中自然语言提问（如“帮我分析一下 1001 客户的健康度与风险”）可自动触发 Tool 并直接生成结构化建议。

### 5. 会话标题智能提炼与自动更新

- 当会话初始标题为默认“新对话”时，在首轮问答生成完毕后（`AiChatStreamFinalizer` 或异步旁路）：
  - 自动提炼用户首个问题的核心业务语义为 4~12 字简洁标题（如“关于北京XX公司的合同咨询”）；
  - 调用 `aiSessionService.updateTitle` 自动更新会话标题，大幅提升多会话管理体验。

### 6. 前端 AI 抽屉交互优化

- 在 `AiAssistantDrawer.vue` 预置高频业务快捷指令药丸（Prompt Starter Pills）：
  - “📊 诊断客户健康度”
  - “📋 汇总今日待办任务”
  - “📈 统计本月商机进展”
  - “📝 起草商业拜访纪要”
- 优化诊断卡片和指标的高亮样式展示。

## 不做什么

1. **零 Flyway 迁移脚本**：诊断数据由业务表实时计算聚合，无需新建存储表，零 DB 迁移；
2. **零新权限常量**：完全复用既有权限常量 `CUSTOMER_VIEW_COMPANY`（117）；
3. **零真跑模型外呼**：单测全程纯 JVM mock，DASHSCOPE_API_KEY 置空；
4. **零不可逆数据写操作**：诊断服务纯只读，不修改任何客户、商机、合同业务数据。

## 验收标准

1. `GET /ai/insight/customer/{companyId}` 正确聚合五实体数据，返回包含健康分、等级、摘要、风险点与行动建议的结构化结果；
2. 权限隔离严格生效：归属人及上级可正常获取诊断，无权限同事访问返回 12002 `PERMISSION_DENIED`；
3. `AiToolRegistry` 注册 `getCustomerInsight` 工具，评测集与单测调用成功；
4. 会话首轮问答后会话标题自动从“新对话”智能更新为提炼标题；
5. 前端 AI 抽屉展示快捷药丸指令，点击一键填充/发送；
6. `mvn -B -ntp test` 全绿，surefire 数量只增不减（基线 1391）；
7. 前端三检全绿（`pnpm lint:check` + `pnpm type-check:check` + `pnpm vitest run` 179 pass）；
8. 四静态 0 违规，`bash scripts/merge-gate.sh` 8/8 PASS 退出码 0。

## 红线

- 诊断异常恒定安全降级回退，绝不抛 500；
- 零迁移、零新权限码、零真跑外呼、保持分支在册未授权严禁 push。
