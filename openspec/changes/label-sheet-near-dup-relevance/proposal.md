# 提案 · label-sheet-near-dup-relevance（人标最小包 + 三情景打分）

## §1 问题

近重复线七张卡 + 评测端口误差条都已收口，**唯一还没被测量过的对象是「人」**：

- 所有结论都建立在「pair 级 `cos`」与「机器生成的 golden id」上，没有一个数字来自**人类对相关性的判断**；
- `0.90` 的拍板依据里最硬的一条是「多压的那几张图是真重复还是真不同，**本语料无标签可判**」——这不是推论，是缺数据的直说；
- 评测端口刚量化出「伪向量低估 `recall@5` 约 9pp」，但**这 9pp 是装置误差还是质量差距**，同样只有人标能回答。

所以本卡不建标注平台、不做标注规范：**只做一张 30 行、两列、15 分钟能填完的表**，加上一套确定性的打分器，让 Owner 的半小时变成可复算的结论。

## §2 标注材料（全部来自冻结资产，零外呼）

| 材料 | 来源 | 是否稳定 |
| --- | --- | --- |
| 6 条查询原文 | `near-dup-rerank-decomposition-v1#queries[].text`（已冻结） | 是 |
| 候选（每查询 top-5） | 本地按生产类重建（`InMemoryVectorStore` → `ImageSimilarityGate` → `Bm25Scorer` → `DefaultWeightedReranker`），语料由 `NearDuplicateCorpus` 程序化生成 | 是（确定性，卡 32–37 已七次复现） |
| 候选 `cos` / `tier` / `band` / 现行名次 | 同上重建 + 卡 35 锚逐条对账 | 是 |
| 候选可读文本 | `NearDuplicateCorpus` 的切片文本（PDF 页切片的图注/正文片段） | 是 |

合计 **6 查询 × 5 候选 = 30 行**。每行两列判断：

- `relevance`：`2`=直接回答该查询 / `1`=同主题有帮助 / `0`=无关
- `isNearDuplicate`：`Y`=与同行集合里更高名次的某张图是**同一张图的变体** / `N`=不是 / `U`=看不出

## §3 本卡做什么

- **腿 A 标注包（零外呼）**：生成 `docs/rag-quality/labels/near-dup-relevance-v1.csv`（30 行）+ 一页填表说明（`…-README.md`）。行 id 固定为 `q{index}:{chunkId}`；顺序 = 现行名次（**不打乱、不按 cos 排**）。
- **腿 B 打分器（零外呼）**：读填好的 CSV → 完整性校验 → 三情景打分（并列、不排序）：
  1. **现状**：生产 `0.982` 口径的排序；
  2. **无降权**：把 `δ` 置 0 的排序；
  3. **0.90 口径**：把门槛降到 0.90 的排序（用同一批候选重算 `cos` 与降权，纯本地）。
  每个情景给 `precision@5`、`NDCG@5`、以及「被判 `isNearDuplicate=Y` 的候选是否正好被压制」的**一致率**。
- **腿 C 守卫**：包与冻结锚逐行一致（id / `cos` / `tier` / 名次）、CSV 完整性与取值合法、**annotator 字段非空且不含 agent/ai/model 字样**、零外呼、锚内无倾向措辞。

## §4 判据（R0–R8）

- **R0 边界**：`src/main` 零 diff、既有 46 张锚零字节变动、不改任何生产常量、**本卡零外呼**（不设任何 `*_REAL`）。
- **R1 包必须确定性**：同提交两次生成**逐字节一致**；行顺序 = 现行名次；行 id = `q{index}:{chunkId}`，不得因重跑漂移。
- **R2 盲标纪律（防引导）**：包内**不得**出现任何结论性提示——不得出现 `tier`/`band`/`cos` 的**排序建议**、不得出现「此候选项可疑 / 应压制 / 近重复」字样、不得引用任何锚的结论；`cos`/`tier` 列**根本不给标注者看**（放行的只有：查询原文、候选文本、行 id、文件名/页号、现行名次）。
- **R3 完整性校验**：打分器必须**拒绝**并报出具体行：空单元格、`relevance∉{0,1,2}`、`isNearDuplicate∉{Y,N,U}`、`annotator` 空或命中 `agent|assistant|ai|model`、日期缺失、行 id 与包不一致、重复行。
- **R4 三情景并列**：`precision@5` / `NDCG@5` / 一致率三情景**并列呈现，不排序、不给推荐**（板规 D4 与卡 36 同源）；锚内不得出现「建议降 / 建议不降 / 应下调」。
- **R5 标注人与时间入锚**：CSV 的 `annotator` 与填写日期写入锚，并记 CSV 的 sha256；**same-byte 复算**（同一 CSV 两次打分结果逐字节一致）。
- **R6 可复认证**：锚由写模式 `-Dlabel.sheet.write=true` 重建；默认复跑逐字节一致（剔除顶层 `runtime`）；纯 LF、单尾换行；md ≤40 行。
- **R7 停手**：任一候选在冻结语料里取不到可读文本 ⇒ 记 `UNDETERMINED`，**不许**自己补写候选文本（补写 = 伪造标注材料）。某查询候选不足 5 条 ⇒ 如实记实际条数，不许凑数。
- **R8 不外推**：本卡结论只对「这 6 查询 × 30 候选」成立；锚内不得出现「生产相关性 / 用户偏好 / 全局质量」类断言。

## §7 裁决假设（可推翻但必须停手上报）

- **D1 只读懂这 30 行**：不做标注规范、不做多人一致性（κ）、不抽样复核——那是标注体系的活，本卡只为回答「压不压」这一个问题。
- **D2 不给标注者看分数**：看 `cos`/`tier` 会让判断向机器靠，等于把标签污染成「机器观点的复述」。
- **D3 三情景不排序**：本卡只产事实（每个情景的指标），拍板仍是 Owner。
- **D4 不代填、不改标**：执行者只能校验格式，不能修正内容；判为 `U` 也是合法答案。
- **D5 失败就停**：若 30 行里可读文本缺失超过 3 行，停手上报（说明语料侧不足），不降级成「只标能标的」。

## §8 判据修订记

- （预置）若三情景在 30 行上**完全打平**（指标全等），如实记录并停手上报——那说明「压制与否」在这批候选上不可分辨，本卡的价值就退化为「已知不可分辨」，不得为了出差异而改口径。
