> 变更：`wire-pmd-ruleset` ｜ 日期：2026-09-21
> 需求↔事实映射：R1←pom 无 `<rulesets>`（实测 `grep -c ruleset pom.xml`=0，28 条声明规则零读者） ｜ R2←10/28 条 ref 在 PMD 7.9.0 不可解析 ｜ R3←阈值两处不相干（`pom.xml:443` 注释 vs `:446` `failurePriority`） ｜ R4←豁免登记与门禁回接（§6.7 到期条件③）
> 上位关系：延续 `harness-gates` 的 R1（门禁声明必须有生效触发点与读者）；本增量把它应用到 Java 静态分析域。

## ADDED Requirements

### Requirement: R1 被审代码的规则集必须真的被加载
构建配置 MUST 显式加载仓库声明的静态分析规则集；被跟踪的规则声明文件 MUST 至少有一个读者。任何"存在配置文件但构建不加载它"的状态都视为门禁缺失而非门禁宽松。加载结论 MUST 以**逐规则命中清单**为凭：声明的每条规则在结果中要么出现（含 0 命中），要么被显式说明为何未参与本轮。

#### Scenario: 孤儿配置文件被判违规
- **WHEN** 仓内存在被跟踪的规则声明文件，而全仓 grep 不到任何加载它的构建配置
- **THEN** 视为该静态分析门禁未生效；MUST 补接线或删除该文件并说明理由，不得以"文件在库里"主张已覆盖

#### Scenario: 打开开关不等于架上尺子
- **WHEN** 仅移除跳过配置使工具可运行，但运行使用的是工具内置默认规则集
- **THEN** 结论不得表述为"仓库规则集已生效"；MUST 报告实际使用的规则集来源，并列出与声明规则集的差异

#### Scenario: 规则静默失效不可接受
- **WHEN** 规则集中某条规则因版本变更不再存在
- **THEN** 构建 MUST 硬错并指名该规则，而非跳过它继续跑；判别式是一次临时的不存在规则名注入实验，且必须可还原

### Requirement: R2 规则引用的可解析性必须有机器判别
被加载的规则集内每条规则引用 MUST 在当前工具版本下可解析。可解析性 MUST 由一条可重复运行的命令判别（构建自身报错或专用校验脚本），MUST NOT 依赖人工比对 jar 内容。修复动作 MUST 逐条留痕：删除 / 替换为等价规则（注明新规则全名）/ 仅调整分类路径，三者之一加依据一句话。

#### Scenario: 等价替换改变语义需可见
- **WHEN** 一条失效规则被就近替换为"名字相似"的新规则
- **THEN** 必须给出替换前后逐规则命中数对照，说明松紧变化；无对照不得合入

#### Scenario: 只是搬家的规则不得被删除
- **WHEN** 失效原因是规则换了分类或文件后缀写法错误
- **THEN** MUST 按新路径修正而非删除该条，以免悄悄缩小覆盖面

### Requirement: R3 阈值口径必须唯一、有读者、且只许变严
静态分析的"多少算失败"MUST 只有一个口径与一个读者（构建配置项或判定脚本）。文档注释 MUST NOT 声称与真读者不符的阈值。以真实运行写入的存量基线（条数或豁免条目）MUST 满足：只允许由一次真实运行更新、数值只许下调不许上调、并配一条"登记值高于当前实测即要求下调"的过期校验。

#### Scenario: 装饰性阈值数字被清出
- **WHEN** 注释或配置里出现一个没有任何读者读取的阈值数字
- **THEN** 必须删除或接上读者；MUST NOT 以"以后会用到"保留

#### Scenario: 基线只严不松
- **WHEN** 一次真实运行的违规数低于登记值
- **THEN** 过期校验非零退出并要求把登记值下调；把登记值改高以"让门禁变绿"MUST 被拒

#### Scenario: 新增违规必须变红
- **WHEN** 新提交引入一条违反已加载规则集的代码
- **THEN** 该检查与本地合并聚合门禁 MUST 非零退出并指名失败子门禁；MUST 以一次真实注入-还原实验为凭

### Requirement: R4 关闭态门禁的解除必须留下真跑证据
任何以"临时跳过 + 登记豁免"存在的质量门禁，解除时 MUST 在被跟踪文档留下"已启用 + 判定依据位置 + 一次真实运行结论"，并把原豁免理由逐条标注为已消除而非删除。真实运行证据 MUST 明确区分"该检查本身真跑"与"依赖外部资源的兄弟阶段是否新鲜"（如无 Docker 时 failsafe 只跳不证）。

#### Scenario: 豁免只活在提交信息里
- **WHEN** 一处被关掉的检查只在提交正文说明理由，被跟踪文档无登记
- **THEN** 视为不合规；必须先补登记（项 / 理由 / 复测命令 / 到期触发条件）再谈解除

#### Scenario: 解除后不补真跑记录
- **WHEN** 跳过配置已删除，但没有一次可复现的真实运行结论落进文档
- **THEN** 不得声称该门禁已生效；MUST 补记录并注明机器与前置条件

#### Scenario: 绑在默认不跑的阶段上的检查
- **WHEN** 某检查绑定在聚合门禁默认跳过的构建阶段
- **THEN** 聚合门禁 MUST 单独调用它（或显式声明其不在默认覆盖内），MUST NOT 因"该阶段属于 verify"而静默失去覆盖
