# 协助关联记录详情内展示

## Why

协助详情中的关联记录目前使用普通列表页或业务详情路由跳转：联系人、公司跳到列表后无法定位记录，商机使用普通详情页会触发“权限不足”，审批记录跳列表后也看不到对应详情。用户还需要反复返回“待我协助”，导致协助处理链路被打断。

## What Changes

- 将协助关联的客户公司、联系人、审批记录、业务活动和联络任务改为当前协助页内的详情弹窗/抽屉展示。
- 商机保留独立详情页展示，但详情页提供“返回协助”按钮，返回来源协助记录而不是返回普通列表。
- 关联详情优先调用带 `assistId` 的受控接口，不再复用普通业务详情路由绕过或触发普通行级权限。
- 详情请求返回 403 或记录不存在时，在当前弹窗内显示可读提示，不跳转列表、不丢失协助上下文。
- 统一关联入口样式，使用紧凑的标签式按钮并明确区分“商机、公司、联系人、审批、活动、任务”。
- 处理协助时，公司、联系人和审批不要求用户离开当前页；商机详情关闭或点击“返回协助”后回到原协助状态。

## Impact

- 影响前端：`AssistRecordLinks`、协助处理/申请详情页及关联详情弹窗组件。
- 可能需要后端补充或确认：按 `assistId` 返回审批详情的受控接口，以及现有商机/公司/联系人协助详情接口的响应契约。
- 不修改普通商机、公司、联系人和审批页面的路由行为；不放宽普通业务权限。
- 继续遵守协助生命周期：待协助期间读取实时关联数据，终态只展示后端冻结快照或历史详情。
