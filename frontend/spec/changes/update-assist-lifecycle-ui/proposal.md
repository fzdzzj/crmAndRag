# 协助申请生命周期前端对接

## Why

后端协助申请已经具备终态快照、已取消状态、过程对话和逐附件删除结果。联络任务的创建人、指派人和执行人还可以在待协助阶段，通过协助专用入口读取/上传任务来源附件并参与过程对话。

当前前端已有任务来源附件的读取/上传控件，但没有消息接口、消息时间线或发送入口；生成的 OpenAPI 客户端也缺少这些接口和 `AssistMessageVO` 类型。因此任务实际参与人虽已获后端授权，仍无法在页面中查看发送者或发送协作说明。

## What Changes

- 将协助详情改为消费通用 `recordSnapshot`，终态只展示冻结数据；历史数据缺少快照时给出明确提示。
- 增加“已取消”状态及其原因展示；终态隐藏上传、删除和发送消息入口。
- 增加可复用的协助过程对话面板，展示发送者姓名、发送时间、正文及系统消息；待协助时可发送，终态只读。
- 在“待我协助”“我的申请”详情，以及从联络任务详情中打开的协助详情内复用对话面板；任务创建人、指派人和执行人可按后端授权参与任务协助对话。
- 申请编辑器仅发送 `assistApplyList`，前端阻止同一次申请的重复协助人。
- 附件删除消费 `deletedIds / denied / notFoundIds`，提示部分成功，不将失败附件从列表移除。
- 以后端导出的 OpenAPI 为唯一契约来源，重新生成客户端类型。

## Impact

- 涉及：协助列表、我的申请、协助详情弹窗、活动/任务/审批的协助申请编辑器及附件组件。
- 新接口：`GET/POST /assist/{id}/messages`；任务来源附件接口：`GET /assist/{id}/task/attachments`、`POST /assist/{id}/source-attachments`；附件删除响应由布尔值变为明细结果。
- 不修改既有业务创建、审批流转与权限菜单；不引入轮询或 WebSocket；本轮不新增前端自动化回归测试。
